# Scope change v8 (2026-10-28) — note to Professor

We would like to narrow the measured applications from Google Meet and Zoom (agreed on 10/14) to **Google Meet (≈30 calls) and Microsoft Teams (≈15 calls)**, both run as web clients in Chrome on the same Windows laptop; if time runs short, we will reduce the Teams calls first. The main reason is ground truth: our Week 1 pilot showed that Zoom offers only an approximate reference (a statistics window with integer fps and no export, cross-checked by screen recording), and we could not confirm that its packets expose RTP headers, which our loss diagnosis depends on. Teams, in contrast, was studied in the vcaml paper we build on, so a prior model and lab data already exist, and in Chrome it can use the same per-second WebRTC statistics we use as ground truth for Meet (to be confirmed in a one-call pilot this week). Keeping both apps in Chrome on one Windows machine also matters for the cause diagnosis: our loss, bandwidth, and CPU-pinning injection tools are Windows-only, and changing the OS and the application together would make it impossible to tell which one caused a difference. With two team members and about five weeks left, this lets us spend the time on accuracy against ground truth, cause diagnosis, and recovery verification rather than on a third app with weak ground truth; Zoom remains a direction for future work, not a claimed result.

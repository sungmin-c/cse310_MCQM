# T13 — P5 실험 도구 보강 (주말 실측 전 안전망)

배경: `scripts/overhead_ab.py`, `scripts/overhead_report.py`, `scripts/mem_hog.py`, `scripts/widget_proxy.html`은 주말 실측(10/31–11/1)에 처음 쓰는 코드다. 통화 없는 시험 실행(capture·server·widget 모드, 25초)만 했다. 실측 중에 죽거나 잘못된 표를 내지 않도록 보강한다. 설계는 `docs/design/overhead_weekend.md`.

## 할 일
1. `overhead_ab.py`에서 단계 목록 만드는 부분을 순수 함수 `build_phases(modes, pairs, step, warm)`로 꺼낸다. 동작은 그대로(warm 먼저, 바퀴마다 시작 단계를 한 칸씩 돌림). 테스트: modes `off,widget`·pairs 3이면 `off,widget | widget,off | off,widget`, 길이·초 확인.
2. 시작 시 입력 검증을 한 곳에 모은다: `--modes`에 모르는 이름이 있으면 시작 전에 종료(허용 목록 `off,on,capture,server,widget,os`), `--pin-monitor`가 논리 코어 수 이상이면 오류, `--pairs`·`--step`이 1 미만이면 오류. 오류는 `ap.error`로 한국어 한 줄.
3. `overhead_report.py` 견고성: `_mem.csv` 또는 `_os.csv`가 없으면 어떤 파일이 없는지 알리고 종료(스택 트레이스 금지), 단계 안에 데이터가 하나도 없으면 그 단계 열을 `–`로 표시, `--dump` 없이도 돈다. `perf_table`은 typeperf 형식(헤더 `"(PDH-CSV 4.0)","\\HOST\Memory\Pages/sec"…`, 값 문자열 따옴표, 시각 `"10/31/2026 14:00:01.123"`, 빈 칸 `" "`)을 합성 csv로 만들어 테스트한다. GPU 열이 여러 개면 합산.
4. 위 변경에 대한 단위 테스트를 `tests/test_overhead_report.py`와 새 `tests/test_overhead_ab.py`에 추가한다. psutil·websockets·tshark·실제 프로세스를 띄우는 테스트는 만들지 않는다(순수 함수와 임시 csv만).

## 하지 말 것
- CLI 옵션 이름·기본값 변경, 새 의존성, 통과 기준 숫자 변경(`overhead_weekend.md` §3), `server/`·`capture/` 수정, push.
- 실제 tshark·Chrome·통화·부하 프로세스를 실행하는 코드를 테스트에 넣기.

## 완료 기준
- `uv run --no-sync pytest tests/ -q` 전부 통과.
- 기본 인자(`--modes off,on --pairs 3`)에서 기존 단계 순서가 바뀌지 않는다는 테스트가 있다.
- 보고에 변경 파일·추가한 테스트 수·바꾸지 않은 동작을 적는다.

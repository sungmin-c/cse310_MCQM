# 예림의 Claude를 위한 작업 가이드 (10/30–11/1 검증 작업 한정)
> 이 문서는 예림이 자기 Claude(Mac)에게 읽히는 규칙이다. 작업 내용은 `docs/team/YERIM_TASKS_1030-1101.md`.

## 시작할 때 예림이 붙여넣을 프롬프트
```
이 repo는 CSE 310 팀 프로젝트 MCQM이야. 내 작업은 Mac에서 하는 검증이다.
1) docs/team/YERIM_CLAUDE_GUIDE.md 와 docs/team/YERIM_TASKS_1030-1101.md 만 읽어줘 (다른 문서는 필요할 때 해당 절만).
2) 오늘 할 항목은 [A0, A1, A2] (또는 [B1] / [B2]) 야. 해당 항목을 순서대로 실행하고, 결과를 docs/reports/yerim/REPORT_1030-1101.md 에 가이드 양식으로 기록해줘.
3) 가이드의 "하면 안 되는 것"을 지켜줘. 코드 수정·커밋·push·설치·시스템 설정 변경은 하지 말고, 필요하면 제안만 해줘.
4) 내가 직접 해야 하는 단계(Chrome 클릭, Meet 입장, 스크린샷, 시스템 설정)는 멈추고 "이제 이걸 해줘"라고 알려줘. 끝났다고 하면 이어서 진행해.
끝나면 변경 / 테스트 / 남은 것 3줄로 알려줘.
```
세션은 하루 한 번씩 새로 시작한다(금요일 A0–A2, 주말 B1, 필요하면 B2). 새 세션에서는 같은 프롬프트에서 항목만 바꾼다. 이어서 쓰는 상태는 보고서 파일이 기억한다.

## 이 작업에서만 바뀌는 규칙 (repo의 AGENTS.md보다 우선)
repo의 `AGENTS.md`는 commit·push·PR을 허용하지만, **이번 검증 작업에서는 아래가 우선한다.**

### 해도 되는 것
- 파일 읽기, `git fetch`/`git checkout -b web/yerim-verify`, `git status`/`git diff`
- 버전 확인(`node -v` 등), `npm ci`, `npm test`, `npm run dev`, `uv run server/dummy_stream.py ...`, 포트 확인
- 임시 스크립트·예시 JSON: **repo 밖** 임시 폴더에서만 (예: `/tmp/mcqm_yerim/`)
- 보고서 파일 작성: `docs/reports/yerim/` 아래만

### 하면 안 되는 것
- 소스·테스트·설정 수정, `server/`·`scripts/`·`docs/`(보고서 제외) 편집
- `git add`/`commit`/`push`, PR 생성, main 병합 (**예림이 직접 한다**)
- 새 패키지 설치(brew/npm install 신규 의존성/pip), `pyproject.toml`·`uv.lock` 변경
- 시스템 설정 변경(인터넷 공유, 방화벽, 네트워크), 앱 설치
- 다른 사람 트래픽 캡처, 메시지·메일 전송
- 대용량 파일(pcap)을 repo에 두기 (git 제외 대상이지만 repo 폴더에도 두지 않는다)

### 막혔을 때
20분 이상 막히면 멈추고 보고서의 "막힌 곳"에 적고 다음 항목으로 간다. 오류 전문을 요약하지 말고 그대로 붙인다.

## 자동화 방식 (예림이 할 일을 줄이기 위한 구조)
- **Claude가 하는 것**: 버전 확인, 설치된 도구 점검, 테스트·서버 실행, 출력 수집, 보고서 작성, 체크박스 갱신
- **예림이 하는 것**: Chrome 클릭, Meet 입장, 스크린샷 저장, 시스템 설정, 커밋·push
- **단계 사이 인수인계**: Claude가 "예림 차례" 문구로 멈추고, 예림이 "끝났어"라고 하면 이어서 진행
- **재개**: 세션이 끊겨도 `docs/reports/yerim/REPORT_1030-1101.md`의 체크박스를 보면 어디까지 했는지 알 수 있다. 새 세션은 이 파일부터 읽는다
- 같은 명령을 두 번 이상 칠 일이 생겨도 스크립트를 repo에 추가하지 않는다. 필요하면 "제안" 절에 적는다

## 보고서 양식 (`REPORT_1030-1101.md`)
```markdown
# 예림 검증 보고서 (10/30–11/1)
작성: <날짜·시각> · 환경: macOS <ver> / Chrome <ver> / node <ver> / uv <ver>

## 요약 (3줄)
- 한 것: 
- 막힌 것: 
- Sungmin이 판단할 것: 

## 항목별 결과
### A0 환경 점검 — 통과 / 실패 / 불가 / 미실시
- 확인한 것(명령과 출력 요약):
- 근거 파일(스크린샷 파일명):
- 미확인:

### A1 …  (A2, B1, B2 같은 양식)
(B1은 ○/× 5개를 표로)

## 내가 직접 한 것 vs Claude가 한 것

## 제안 (코드 변경이 필요해 보이는 것. 실행하지 않았음)

## 다음에 필요한 것
```
규칙: 결과는 **통과 / 실패 / 불가 / 미실시** 넷 중 하나로만 쓴다. "아마 된다"는 쓰지 않고, 확인 못 한 것은 "미확인"이라고 적는다. 수치는 출력에서 그대로 옮긴다.

## 결과를 Sungmin이 읽는 순서
1. 요약 3줄 → 2. 실패·불가 항목 → 3. "Sungmin이 판단할 것". 그래서 요약 첫 줄에 가장 중요한 것(예: "대시보드 코드가 repo에 없음")을 쓴다.
